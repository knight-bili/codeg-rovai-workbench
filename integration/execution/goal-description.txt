持续推进 Codeg × Rovai 完整一期融合项目，完成既定 I00–I12 及 BUF。以 Rovai Core 为唯一业务、执行和数据库权威，保留已确认的 81 个来源功能簇、48 个工作包和 324 个工程验证场景，交付完整、高可用、可扩展、可以实际使用的融合 MVP。一期包含两个应用的既定融合范围，以及必要的整改、兼容、迁移和缺陷修复；不得为了缩短工期擅自删除功能。第二阶段才规划自主新增能力。
**分工：**Codex 负责设计细化、技术架构、编码、自审、代码审查、测试、构建、集成、GitHub 仓库及 PR 管理、阶段收口和缺陷修复。I12 工程完成前，用户只审核确需确认的方案，并提供 Codex 无法自行解决的环境、身份、预算、设备等外部条件。已经确认的方案直接实施，普通实现选择和修复由 Codex 自行处理。
**验收定义：**“客户验收”仅指 I12 必需研发和工程验证完成后，用户拿到可运行的完整软件，以真实用户身份使用并反馈是否满足需求。用户不承担阶段技术测试、PR 审查、测试报告审核或逐项执行 324 个场景。上述工程工作全部由 Codex 完成；客户使用反馈引出的缺陷仍由 Codex 修复并回归。
**阶段推进：**I00–I12 内部使用“研发实现”和“工程验证”表述，准确区分开发中、代码完成、工程验证中、工程验证通过、待环境验证。每阶段维护有限的剩余清单、完成条件和下一动作，由 Codex 自行判断是否满足阶段收口条件，不将“等待客户验收”作为推进障碍。发现问题按所属阶段处理；不能把后续阶段全部提前塞入当前阶段，也不能遗漏当前阶段的必需工作。暂缺外部条件时登记待办，继续可以独立完成的工作，最终 MVP 的必需实现和验证仍须补齐。
**提交与验证频率：**采用多次本地 commit、阶段集中验证、少量 push。小功能、缺陷和调整先编码、自审并完成适当的低成本检查，再用中文本地提交；不逐切片默认全量编译、全仓回归、推送或触发 Actions。I01–I12 正常各一个阶段候选验证批次，共 12 批；阶段代码与审查集齐后冻结候选版本，集中执行相关构建、测试、集成和平台验证，再推送并触发必要的 Actions。修复失败项时增加候选批次，记录原因并完成必要回归。等待远程结果期间继续独立开发。
**资源与授权：**优先使用免费资源，不提高支出上限、不自动采购或运行付费模型。确需用户协助时提出具体事项，同时继续独立工作。main 最终合入、正式发布及费用支出保留用户授权。
**交付与汇报：**I12 工程完成后交付可运行软件、必要使用说明、完整范围对照、工程验证结果和真实遗留问题，再交用户使用验收。每轮报告新增完成、实际验证、具体未完项、下一动作及确需用户处理的事项；不以局部测试数量代替阶段完成。全部必需研发、工程验证和最终客户软件使用验收完成前，不将持续目标标记为完成。
